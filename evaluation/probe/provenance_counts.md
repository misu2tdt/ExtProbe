# Attribution check on the canary / demo fixture: requests per pattern

Generated by `evaluation/probe/provenance_counts.py` on 2 v3 runs of the fixture. Counts only, no extension ids.

**Ground truth.** The fixture's code decides, by construction, which host each request goes to, so the true context of every counted request is known before the run (hosts and their sources: `examples/canary/content.js`, `sw.js`, `target_probe.js`; the page's own request: `sandbox/base/honey_pages/universal.html`). A request is counted as correct when the recorded attribution equals the true context (service worker, content script or page; the content-script vs other-extension-code distinction is read from the outermost extension frame against the manifest's `content_scripts` files). One request per page visit is recorded, so a pattern has several requests per run.

Generated by `py eval/v3/labels/build_labels.py`. Metadata only: no `.crx` downloaded, the MADWeb zips were only listed (central directory), nothing was extracted. Labels, scoring, sandbox and image are unchanged. Sources, commits, dates, licences: `sources.md`.
## Summary

- Tiers (313): T1 120, T2 154, T3 39. Without Sentry's per-record source URL: T1 120, T2 10, T3 183. Most T2 evidence is the vendor URL that Sentry attaches; GF alone cites mostly THN (news).
- T1 is 0 from MADWeb (517 IDs, none among the 313), 47 from TPCI human-reviewed, 73 from the static Stage 5A verdict (only 73 on that alone, 62 of them in F000). Stage 5A `malicious` = risk >= 100 or any critical finding, e.g. a known malicious C2 domain (SCHEMA.md); it is a static verdict, and the findings behind it are not in the CSV, so whether it is independent of the source list cannot be checked here.
- Recall @40, verified-malicious only, v2 / v3: T1 79/113 = 69.9% / 9/111 = 8.1%; T2 86/138 = 62.3% / 24/136 = 17.6%; T3 22/32 = 68.8% / 8/31 = 25.8%; all 187/283 = 66.1% / 41/278 = 14.7%.
- Recall does not rise with label confidence. v3 @40 (verified-malicious) goes T1 -> T2 -> T3: 8.1% -> 17.6% -> 25.8%; without F000 (101 samples, 62 T1 / 39 T2, v3 flags 0): 18.4% -> 24.5% -> 25.8%. The T1 gap is mostly F000; the rest is small groups (T3: 32), so no tier effect can be claimed in either direction.
- Sentry: 9 of 497 benign dev/test IDs are listed (v3 flags 3 of 9); TPCI: 19. Labels unchanged; see `sentry_overlap_benign.md` and section 5. Test-set items such as a Sentry `Malware` record for a benign-labelled test extension should go to the labelling review before the test FPR is quoted again.
- MADWeb overlap with the dev set: 0 malware, 0 benign (ID match). A MADWeb test set can use all 517 IDs.


## Tier definition

- **T1 verified-behavior**: ID in MADWeb, **or** a TPCI record that is human-reviewed (`CONTRIB-METHOD` without `Delta_Import` / `csv_import` / `PDF_Import`, per the README "independently verified entries"), **or** TPCI Stage 5A verdict `malicious`. Stage 5A is *static* analysis (TPCI-V.md), so the basis is kept in `t1_basis` and sub-reported below.
- **T2 vendor-report**: not T1, and at least one cited source URL (GF `source_url`, TPCI `SOURCE`/`ARTICLE`/`ADD-SOURCES`, Sentry `source`) is on a security vendor / researcher site that publishes technical analysis (list in `build_labels.py`, `VENDOR`). Decided by publisher type; the articles were not opened, so "the article lists this ID" is trusted, not checked.
- **T3 news-aggregated only**: everything else.
- Presence in Sentry does **not** raise the tier (the repo warns of false positives). Only the vendor URL in its `source` field counts as a cited source; the column `tier_excl_sentry_url` shows the tiers without that.

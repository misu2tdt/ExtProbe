# Reproducing the results

Three levels, from cheapest to most expensive. The first two need no Docker and no recorded traces.

## 1. Checks that run from this repository

```bash
pip install -e ".[dev]"                                    # or: pip install -r requirements-dev.txt
python -m pytest -q                                        # unit tests and detector cases (no Docker)
extprobe verify-freeze                                     # frozen files unchanged (sha256 of content)
python evaluation/v2/check_paper_numbers.py --precomputed  # paper numbers from the precomputed result files
```

- **`verify-freeze`** compares every file listed in `PROVENANCE/frozen_files.tsv` (scoring, sandbox v3, run scripts, test-set hash, canary, …) with its recorded sha256. Expected: `50 frozen file(s) match their recorded sha256, 0 differ or are missing; 23 frozen file(s) deliberately not carried`. The 23 are v2 service code and exploration scripts that were frozen in the private repository but are not published (listed as `NOT CARRIED`).
- **`check_paper_numbers.py --precomputed`** recomputes the v2 precision/recall figures (AUC, TP/FP/FN/TN at threshold 40, with the raw labels and with the labels after the manual label review; the latter are named `verified` in the files, which does not mean the behavior was verified) from the four files in `evaluation/v2/precomputed/` and checks them against the paper. Expected: **10/12 PASS, 2 SKIPPED**. The two skipped checks, *`summary.csv` regenerated byte-identically from the traces* and *traces untouched*, need the 354 recorded v2 traces, which are a release asset (Zenodo DOI: available before submission). Unpack them into `data/v2_results/` (or set `EXTPROBE_V2_RESULTS`) and run the script without `--precomputed` to get 12/12.

Scripts in an `as_run/` folder are kept exactly as they were run, as a record; they read private inputs and are not runnable in this layout.

Re-scoring the archived traces reproduces all reported scores and flags exactly (1,319 traces, 0 mismatches); live re-runs can differ for timing-dependent detectors (10/11 identical flags in a smoke re-run); see [evaluation/reproducibility.md](evaluation/reproducibility.md). The blind labelling of the in-the-wild audit is summarized in [evaluation/v3/in_the_wild/labeling.md](evaluation/v3/in_the_wild/labeling.md).

## 3. Re-running the sandbox yourself

You can run any extension through the sandbox and compare with the committed scores. This needs Docker and the images; the canary is the reference:

```bash
# exact reproduction: the frozen image (README, Option A: a registry image will be published before submission), then
extprobe analyze examples/canary --out out/
# or build from source under new tags (any OS; never touches extprobe-sandbox:* tags), then
python docker/build.py
extprobe analyze examples/canary --image extprobe-local:v3 --out out/
# expected in both cases: 100, Flagged for review, credential_exfil, local_harvest, unsolicited_tab
```

Local image ids are not reproducible between builds. A source build has a different id from the frozen image (`--image` skips the id check); the build is pinned by the base-image digest, `sandbox/base/requirements.v2.txt` and the sha256 of every frozen file. The ids used for the evaluations are in `PROVENANCE.md` (section 4).

## 4. How to read PROVENANCE.md

`PROVENANCE.md` answers one question: **were the criteria fixed before the runs they judge?** The development was done in a private repository with full history that is not published. Instead, `PROVENANCE.md` records:

- the freezes (`v2.0-freeze`, `v3.0-freeze`) with the commit and date that fixed detectors, weights, the threshold of 40 and the held-out test-set hash;
- every version of each criteria document (evaluation, probe trial, scoring, test sets) with its commit, date and sha256, in `PROVENANCE/criteria_history/`; the amendments are append-only, and the few exceptions are named and explained;
- which results were committed after which criteria, and which amendments were written after a run (before any score was read);
- the image ids used, and what was left out or anonymized for publication (`PROVENANCE/modifications.tsv` lists each difference between a published file and its private original).

Dates are git author dates on the author's machine; only the order of commits is relied on. `extprobe verify-freeze` checks the frozen files against their recorded hashes.
